# 首页完成计数的最小修复

本次生产代码仅修改 App.jsx 的 completedToday：复用完成记录页面的 currentWeekCompletions，再按浏览器本地日期筛选，并兼容 completed_at / completedAt。没有数据库迁移、新依赖、事件队列、RPC、登录调整或同步调整。

此前准备的同步重构已撤回。迁移只曾在隔离的 PGlite 内存测试库执行，本任务未在生产执行迁移或部署；此前生产取证使用只读 GET。本次撤回未连接生产数据库，不能据此排除其他操作者曾修改线上数据库。

## 修复边界

- 修复“云端日志3条、状态完成数组1条”导致的两处显示不一致。
- 保留原来的数据选择策略：有本周日志时优先使用日志，否则依照现有规则回退到状态数组。
- 日志写入失败时，完成记录仍可能未保存；没有新增持久重试或事务。
- 日志已有数据时，新完成通常在日志写入成功并返回后反映到首页，未增加乐观合并。
- 原状态数组仍可能因清空、保存失败、旧快照或多端覆盖而变化；本次不修复底层双写一致性。
- 不恢复从未写入日志且已丢失的记录，不修复重复写入，也不增加跨端实时刷新。
- 日期继续使用浏览器本地时区和现有 currentDate 更新机制；午夜更新可能等待原有日期检查触发。

回归测试直接执行 App.jsx 内的真实计数表达式，结合原有完成记录选择器验证来源不一致、清空重装、字段兼容、午夜边界及日志更新。测试不连接云端，也不修改业务数据。
