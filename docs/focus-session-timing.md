# 专注会话计时与恢复

本次仅修改前端计时和专注结束入口，没有数据库迁移或部署。

- 在独立 localStorage 键 `gacha-focus-session-v1:<用户ID或guest>` 保存会话。包含任务 ID、设定毫秒数、剩余毫秒数、状态和预计结束时间。开始、暂停、继续、结束、清除均同步写入，不等待 React effect 或云端防抖。
- 预计结束时间在开始/继续时计算；每次 tick、visibilitychange、pageshow 按截止时间重算。后台是否执行回调不影响已保存的截止时间。
- 页面重新加载后，待现有账号和云端状态加载流程就绪，再匹配待完成任务恢复会话和专注画面。已不在待完成列表中的任务不会恢复。该方案是同设备、同浏览器的恢复，不提供跨设备接续；现有登录/同步加载、本地存储可用且未被清理是恢复前提。
- 主动暂停冻结剩余毫秒数；继续时重新计算截止时间。完整结束记录截止时间，分钟数等于本次设定值。提前完成记录点击时间，分钟数按实际运行时间四舍五入，最少 1 分钟。
- 缺失/损坏会话无法可靠还原历史时间：回退点击时间和最低 1 分钟，并显示提示。绝不以缺失字段创建无效日期。校验版本、任务 ID、状态、时长和剩余时长范围、结束时间有限且为正、异常未来时间。设备时钟被手动修改不在本次处理范围。
- 放弃和重置会清除持久会话；完成后亦清除。放弃保留待完成任务，不写完成日志。结束画面新增“放回扭蛋机”，沿用原有放弃确认。
- 已结束会话跨午夜后点击，完成时间和所属周按原定结束时刻处理。

测试分工：`focusSession.test.js` 验证纯计时及持久化；`focusIntegration.test.js` 执行 App 中真实恢复、结算处理函数；`focusReturn.test.js` 单独验证结束画面按钮及放弃/取消行为。测试模拟进程内存丢失、后台无 tick、暂停和延迟点击；不等同于真实手机系统杀进程测试。
